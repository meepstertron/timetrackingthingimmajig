# Spec

This document is meant to outline the basic definition on how the time tracking tool developed in this repository works at a high level.

> [!WARNING]
> This spec is obsolete and is no longer guaranteed accurate. kthx

## How does it work?

it works by capturing changes in "Layers"

the original design has 3 layers:

 - Layer 1: A process listens on file changes on your drive to the project folder, ignoring dependencies and .gitignores this captures changes done by anyone. a human or AI or agent


 - Layer 2: A seperate process running globally counts keystrokes. It measures KPS and burstyness of typing. this also acts as a sort of presence monitor for the human.

 - Layer 3: For popular Harnesses (Claude code, opencode, etc.) you can use the logs and/or their API's hooks as a sign of truth Claude exposes hooks for when a prompt is sent or when tools get called.

 ## What does NOT get uploaded to the server

 - Full Diffs
 - Keystroke content
 - File changes outside designated projects
 - Plaintext prompts
 - Keystrokes outside User designated Editors


 ## How do we calculate time from these values?

 T1 Gives us a rough estimate of how much time was spent working on the project. this should be treated as low value unverified hours. This allows us to catch any changes done by any agent or IDE even future ones which arent officially supported.

 By using T2's data we can narrow it down fully. now we're at hackatime's level. How much a human typed. how fast. which file. We can deflate T1's estimate using the Data collected in T2.

 Now we have the Human input but not actually productive struggle. Or any time done by a harness. 

 T3 collects events and logs done by agents. instead of relying on the agent self admitting "Hey im coding rn" it allows T1 data to be narrowed down and basically vetted for.

## Limitations

This approach isnt perfect. We cannot reliably differ from productive struggle while thinking and just sitting there and not touching the computer.

## Fraud detection mechanisms

Some possible ways of detecting fraud are:

 - Realistic timestamps (a human has to sleep)
 - Does T1+T2+T3 tell a coherent story
 - How consistent is the Characters Per second.
